# 頂層排版指南（`view`）

頂層圖是手排的，因為它決定使用者第一眼對架構的理解；子層由網頁自動排版。

## `view` 欄位

```json
"view": {
  "w": 1285, "h": 720,
  "layout": {"block_id": [x, y, w, h, ["第二行", "第三行"]]},
  "routes": {"from>to": [[x1, y1], [x2, y2], …]},
  "bands": [{"x": 0, "y": 8, "w": 1285, "h": 84, "label": "① 行程啟動", "lx": 1275, "ly": 30, "anchor": "end"}],
  "cols": [{"x": 10, "y": 124, "text": "userspace 邊界（輸入）"}],
  "nolabel": ["wan>post_evt"]
}
```

- 每個區塊都要有 `layout`，否則 build 報錯。
- 方塊內第一行是區塊 `title`，之後是 `layout` 裡的短說明（每行約 14 個中文字以內）。高度大約是 `16 + 行數 × 14`。
- `bands` 是背景色帶（分層），`cols` 是欄位標題，`nolabel` 列出要隱藏標籤的邊。

## 建議版面

以資料流由左到右、時序由上到下：

```
① 初始化帶（y≈20）：  main / 設定 / …（只跑一次的東西）
② 執行期帶：
   輸入邊界 │ 事件來源 / 執行緒 │ 匯流點 / 佇列 │ 處理物件 │ 輸出封裝 │ 輸出邊界
③ 共用定義帶（底部，選用）
```

- 欄寬 170–190，欄距 35–45；同欄方塊垂直間距 ≥ 12。
- 被很多來源指向的匯流點（如 `PostEvt`）可以畫成很高的方塊，讓每個來源都能水平接進去。
- 邊界節點（`ext`）放最左（輸入）與最右（輸出）兩欄。

## 邊的路線

自動路線（沒寫 `routes` 時）：
- 兩個方塊的 y 範圍重疊 → 在重疊段中間畫水平線。
- x 範圍重疊 → 垂直線。
- 都不重疊 → 在兩塊之間轉一次，最後一段水平停在面對那一側的中點（目標在右就從左邊進入）。不要停在角上。這條線仍可能穿過其他方塊，需要時用 `routes` 改道。

需要手動繞線的情況：L 形會穿過方塊、多條線要共用一條「車道」、回授線（處理物件 → 匯流點）。技巧：
- 在欄與欄之間預留 10–20 px 當車道（例如 x=815 給分派、x=845 給回授、x=1062 給規則封裝），同一車道的線重疊看起來就像匯流排。
- 回授線走到最上方的水平車道（例如 y=110）再往下接回匯流點的頂端。
- 同一來源到多個目標時，起點用同一個點，讓它們從一處分岔。
- 標籤會畫在最長的那段線中間，若會壓到方塊就把邊放進 `nolabel`。

## 子層（自動排版，不需設定）

由左到右：`in` / `case` → `fn`（依呼叫深度往右）→ `data` → `ref`。每個方塊 200×46，1:1 顯示，太寬時左側面板水平捲動。若某層超過約 7 欄或 25 個節點，考慮把一部分移到第三層。

## 檢查

環境沒有瀏覽器時無法看到實際畫面。至少確認：
- 沒有兩個方塊重疊（比對每對方塊的矩形）。
- 每條手動路線的端點落在來源 / 目標方塊的邊上。
回報時要說明「排版尚未在實際瀏覽器確認」。
